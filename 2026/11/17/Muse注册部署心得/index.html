Muse 注册部署心得：把生产服务器交给 AI 管之前，先让它只读巡检

前言：前任太占地方了

站里之前写过一篇《Hermes-agent 的安装与使用》，那是我把 AI Agent 直接装进服务器的尝试。装完才发现，我这台服务器只有 2 核 CPU、1.6 GB 内存，一个本地 Agent 常驻下来，光它的目录就占了 2.9 GB 磁盘，内存也一直紧巴巴。

后来我想通了：Agent 不必住在服务器里。让它住在云端，我这边只给它留一条 SSH 通道，服务器该跑业务跑业务，一点不挤。这篇文章就是这次“换岗”的记录：注册 Muse、把它调教成顺手的样子，最后让它接手这台生产服务器的日常运维。

一、注册：最难的一步

说出来有点反直觉：整个流程里最难的反而是注册这一步，难倒了一大批人。它对网络环境相当挑剔——IP 必须“干净”，最好是家庭宽带的出口；机房 IP、共享代理、来路不明的 VPN 节点，很容易直接触发风控。

我自己的号就是这么下来的。先是挂着平时用的节点兴冲冲去注册，页面转了半天圈，最后甩给我一个验证失败；不死心，又换了两三个节点，一个比一个慢，好不容易有一个走到了提交，又被拦了。当时还纳闷，这产品是怕人用还是怎么的。后来刷到别人的吐槽才知道，要用家里宽带那种“干净”的 IP。当晚回家连上 Wi-Fi，一次过，前后不到五分钟。合着我之前折腾的那两个小时，全耗在跟风控斗智斗勇上了。

熬过这一步，后面反而都顺了：

  • 邀请码入口藏得有点深：网页版在「设置 → 通用 → 用量」里兑换；手机 App 在设置里填，而且兑换窗口有限，拿到码尽早用。
  • 多端是同一个账号：网页、Mac App、iOS App 登录同一个号就能无缝接续，聊天记录、记忆、设置全同步。Windows 暂时没有桌面 App，用网页版即可，功能没缺。
  • 手机配对值得一开：把 iPhone 配对进来之后，它能读到提醒事项、日历这些信息，很多事不用我再手动转述。

二、先让它“认识你”

普通聊天机器人是聊完就忘，Muse 有一套长期记忆：称呼偏好、语言习惯、正在推进的目标，它都会存下来，下次对话直接接着用。

我的配置是：称呼我为“主人”，文字用中文、不用敬称，语音条用英文音色。这些听着像小事，但配合久了会发现，不用重复交代背景才是 AI 助手真正的效率来源——我甚至把“减脂到 70 公斤”的计划和一个重要纪念日的第 1000 天提醒都托管给了它，每天定点巡检、到点提醒，比我自己记日历靠谱。

三、部署重头戏：让它接手服务器运维

1. 先分清：它的电脑不是你的服务器

Muse 有一台自己的云端“工位机”（大概 1.5 核共享算力、6 GB 内存的 Linux 沙箱），浏览器就跑在上面，配置不高，而且会被平台定期回收重建。它适合干活，不适合当生产机。真正的生产服务器还是我这台阿里云 ECS（Debian 13，2 核 / 1.6 GB / 40 GB 盘），跑着 nginx、MariaDB、Waline 评论和几个小服务。

2. 第一个坑：出站 SSH 默认是关的

我把 root@服务器IP 发给它让它试连，连接刚建立就被它那边的权限网关掐了，提示写得很直白：需要在 Muse 设置 → 权限（Permissions）→ Direct network protocols 里，把 ssh 从 Deny 改成 Ask。改完之后每次连接都会走授权确认，这其实是个好设计——权限在自己手里收放。

3. 密钥登录，别给密码

我在服务器上把它的 SSH 公钥加进 ~/.ssh/authorized_keys，全程没有在聊天里发过任何密码或私钥。这里还有个小坑：它的运行环境里家目录不固定，连接时要显式指定密钥路径（-i 到具体的 id_ed25519），否则会吃一个 Permission denied。

4. 约法三章：只读起步，改动先批

连通之后我没有直接放权，而是定了三条规矩：

  1. 先只读巡检：系统版本、负载、内存、磁盘、服务状态、监听端口、容器健康，只看不动。
  2. 每天定时巡检，异常才告警：巡检定在每天上午约 9:24，磁盘、内存、关键服务、SSH 爆破次数这些出问题才来喊我，全绿就保持沉默。
  3. 任何改动先报备：改配置、重启服务、删文件，一律先说明方案，等我确认。

第一件让它动手的事，是卸载之前那位“前任”Hermes：先把配置打包备份，再删除目录和命令文件，释放约 3 GB，删完立刻复查所有关键服务——全绿。顺带把服务器的 git 提交身份改成了它的署名（Aina-大肥鱼），以后谁提交的一目了然。这台机器的 GitHub 凭据本来就在（服务器密钥绑着我的 GitHub 账号），所以它拉代码、推博客仓库都是现成通道。

四、几点心得

这次换岗让我确认了两件事。第一，权限这东西，够用就行，不用贪多：Ask 模式加密钥登录，再加只读起步，出了问题也烧不到业务。下一步我打算关掉 root 的密码登录，只留密钥。第二，流程比“聪明”重要：巡检、报告、确认、执行、复查，一步一步走，比它自作主张瞎折腾强得多。小机器也别硬塞本地 Agent，云端 Agent 加一条 SSH 通道，轻得多，也稳得多。

还有一点是这次才体会到的：它记得这台机器的服务清单、博客的部署链路（源码仓 → GitHub Pages → CDN）、甚至证书到期时间。运维最怕的就是“上次是怎么配的来着”，现在不用怕了。

结尾

这篇博客本身就是新流程的产物：我在聊天里丢了个题目，它在服务器的博客仓库里起草，署名 Aina-大肥鱼，我过目点头之后才发布。从“自己运维”到“指挥 AI 运维”，心态转变大概就是一句话——重复的活交出去，拍板的事留给自己。

下一篇预告：给这台小机器做一次完整的安全加固（关密码登录、收公网端口、备份策略），过程同样会让它先出方案、我再批。
